## Инцидент: карточки без фона

### Симптом

После перехода на настоящий `SectionList` блоки главной отображались прозрачными, хотя токены темы были корректными.

### Диагностика до исправления

````json
{
  "bodyClasses": "apple home-active",
  "vars": {
    "backgroundSecondary": "#efeff4",
    "secondary": "#efeff4",
    "section": "#fff",
    "surface": "#fff"
  },
  "colors": {
    "body": "rgb(239, 239, 244)",
    "sectionList": "rgba(0, 0, 0, 0)",
    "section": "rgba(0, 0, 0, 0)",
    "container": "rgba(0, 0, 0, 0)"
  },
  "rootClassInDOM": "aiwa-sections",
  "deslopContainerClass": "_container_125s3_22",
  "computedRadius": "0px"
}
````

### Корневая причина

В приложении было:

````jsx
<SectionList className="aiwa-sections">
````

В собранной библиотеке корневой компонент фактически создаётся в таком порядке:

````js
jsx("section", {
  className: styles.root,
  ...restProps
})
````

Поэтому `restProps.className` перезаписывал `styles.root`. После потери `_root_125s3_1` переставали совпадать вложенные селекторы:

````css
body.apple ._root_125s3_1 section ._container_125s3_22 {
  background-color: var(--tg-theme-section-bg-color);
  border-radius: var(--ui-component-section-radius);
  overflow: hidden;
}
````

### Исправление в приложении

Пользовательский `className` убран со всех трёх `SectionList`. Необходимые локальные параметры переданы через `style`, который не удаляет системный класс:

````jsx
<SectionList style={{ paddingBottom: "calc(112px + env(safe-area-inset-bottom))" }}>
<SectionList style={{ minHeight: "100%" }}>
````

Исправлены:

- главный экран;
- журнал;
- календарь.

### Диагностика после исправления

````json
{
  "root": {
    "className": "_root_125s3_1",
    "background": "rgb(239, 239, 244)"
  },
  "container": {
    "className": "_container_125s3_22",
    "background": "rgb(255, 255, 255)",
    "borderRadius": "26px",
    "overflow": "hidden"
  },
  "sectionCount": 4
}
````

Проверка журнала:

````json
{
  "rootClass": "_root_125s3_1",
  "background": "rgb(255, 255, 255)",
  "radius": "26px"
}
````

## Предложения по улучшению Deslop

### 1. Исправить объединение className в SectionList

Рекомендуемый контракт:

````jsx
function SectionList({ children, className, ...props }) {
  return (
    <section {...props} className={cx(styles.root, className)}>
      {children}
    </section>
  );
}
````

Это позволит расширять компонент без потери обязательного системного класса.

### 2. Проверить аналогичный паттерн во всей библиотеке

Стоит найти компоненты, где используется порядок:

````jsx
<Element className={styles.root} {...restProps} />
````

Если пользователь передаёт `className`, он заменит внутренний класс. Безопаснее извлекать `className` отдельно и объединять через `cx`, `clsx` или внутренний helper.

### 3. Добавить regression-тест

Минимальный тест для `SectionList`:

- рендер с пользовательским `className`;
- в DOM одновременно присутствуют системный и пользовательский классы;
- Apple container сохраняет surface background и section radius;
- Material card сохраняет собственный background/radius;
- `style`, `aria-*` и `data-*` продолжают пробрасываться.

### 4. Документировать extension API

В showcase/README полезно явно указать:

- разрешён ли `className`;
- как безопасно менять layout без нарушения темы;
- на какой элемент попадают `style` и DOM props;
- чем отличаются карточные контейнеры Apple и Material.

### 5. Закрепить проверку пакета

Текущий проект проверяет:

- точную provenance локального пакета;
- импорт только публичных Deslop UI primitives;
- отсутствие самодельных навигационных SVG;
- наличие production bundle;
- сохранение browser bridge к существующей логике.
