# AIWA post-fix staging load test

Дата: 2026-07-28. Target: изолированный staging на i167. Генератор: 8GPU.
AI route: shared LiteLLM i196 → OpenRouter → текущая
`deepseek/deepseek-v4-flash`. Модель не менялась.

## Итог

Этапы 1–4 исправили HTTP/SQLite bottleneck: обычные экраны устойчиво прошли
ступени до 300 пользователей. Durable queue принимает AI-задачи и сразу отдаёт
fallback, однако текущий provider route не готов к очереди 100+: массовые
пустые ответы одного upstream и давление на память shared i196 являются
stop-факторами этапа 5.

На ступени 100 из 36 failed jobs 35 были связаны с пустыми HTTP 200 от
OpenRouter upstream Novita. Повтор текущей модели не обеспечил требуемые 99%.

## Safety stop

Во время `cold-open-100`:

- LiteLLM оставался ready и не рестартовал;
- его cgroup достиг примерно 630 МБ;
- host `MemAvailable` кратковременно упал до 85–107 МБ;
- LiteLLM использовал около 1,09 ГБ swap;
- stop-guard остановил только `aiwa-staging`; durable queue и БД сохранились;
- после остановки память восстановилась, staging был поднят обратно.

Ступени AI 300 и 1000 сознательно не запускались: это создало бы риск для
других пользователей i196 без добавления полезного доказательства.

## Стоимость

Инкрементальная подтверждённая стоимость post-fix AI-ступеней:
`$0.014247171`. Кумулятивно во всём staging ledger:
`$0.035037273`.

Это нижняя подтверждённая граница: 89 provider-вызовов без cost header не
считаются нулевой стоимостью.

## Решение перед продолжением

Нужно отдельно выбрать один из вариантов этапа 5:

1. оставить модель, но исключить проблемный OpenRouter upstream для
   `today_note` и повторить capacity test;
2. оставить модель, но изменить reasoning/completion budget и проверить
   качество/стоимость;
3. изолировать LiteLLM для AIWA на i167 либо ходить из staging в OpenRouter
   напрямую, чтобы не использовать память общего i196;
4. только после отдельного сравнения рассматривать другую модель для
   `today_note`.

До решения staging ограничен двумя background workers. Обычные экраны,
fallback и `/health` остаются доступны.
