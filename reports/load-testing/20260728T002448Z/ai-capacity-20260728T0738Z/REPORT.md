# LiteLLM / OpenRouter capacity test

Дата: 2026-07-28 07:38–07:50 UTC.

Маршрут теста совпадает со staging-приложением:

`i167 → SSH tunnel 127.0.0.1:14000 → LiteLLM i196:4000 → OpenRouter → openrouter/deepseek/deepseek-v4-flash`.

Промпты, ответы и ключи в результаты не записывались. Нагрузка повышалась
ступенчато, между ступенями проверялись readiness, CPU, память, swap и рестарты
общего LiteLLM. До concurrency 64 тест не повышался: на 32 коротких запросах
throughput уже снизился, а на 16 реалистичных запросах появились ошибки.

## Вывод

LiteLLM на i196 не является текущим bottleneck. Во всех ступенях:

- readiness отвечал успешно; максимальный p95 для реалистичных ступеней — 16,9 мс;
- CPU LiteLLM оставался около 0,03–0,05 ядра;
- рабочая память cgroup оставалась примерно 233–252 МБ;
- рестартов не было;
- активного роста swap во время теста не было.

Для текущей модели и промпта `today_note` безопасная подтверждённая
параллельность — 8. Ступень 12 прошла, но без достаточного эксплуатационного
запаса. На 16 полезная успешность упала до 91,67%, throughput снизился, а два
upstream-провайдера вернули HTTP 200 без пользовательского текста после
расходования всего лимита в 600 completion tokens.

Рекомендация для приложения: общий AIWA-лимит 8, из него 2 слота зарезервировать
для интерактивного чата, а массовому `today_note` дать 6 слотов. Все задачи
принимать в durable queue с дедупликацией; HTTP-экран не должен ждать генерацию.

## Очередь из 1000 сводок

По подтверждённому sustained-результату concurrency 8:

- если отдать все 8 слотов `today_note`: около 15,9 минуты;
- если оставить 2 слота чату и дать сводкам 6: ориентировочно 18 минут;
- последние пользователи не должны держать HTTP-соединение всё это время:
  экран сразу показывает fallback, позицию и ETA, а результат сохраняется и
  подставляется после готовности.

Эти оценки относятся к одной LLM-операции `today_note` на пользователя. Чат,
который делает несколько последовательных модельных вызовов, должен иметь
отдельную приоритетную очередь и отдельную модель/лимит.

## Стоимость

- Все capacity-вызовы, включая первоначальную калибровку: **$0.009768143**.
- Реалистичные `today_note`: **$0.008732057** за 124 вызова.
- Короткие основные ступени 2–32: **$0.000991270** за 168 вызовов.

Стоимость взята из `x-litellm-response-cost`; для всех 296 вызовов значение было
получено. Первоначальная калибровка с `max_tokens=16` дала пустой ответ и после
этого была исправлена на 96 токенов; она включена в полную стоимость, но не
используется для оценки capacity.

## Что менять

1. Durable queue для тяжёлых AI-задач, per-user/day singleflight и idempotency.
2. Общий лимит AIWA 8: chat reserved 2, background `today_note` 6.
3. Быстрый fallback и job id/position/ETA вместо ожидания LLM внутри HTTP.
4. Для `today_note` использовать модель без длинного reasoning либо отдельно
   ограничить reasoning; 600 токенов у текущего маршрута иногда уходят целиком
   без итогового текста.
5. Настроить retry пустого HTTP 200 на другом upstream/модели и не считать такой
   ответ успехом.
6. После реализации очереди повторить cold-open 100/300/1000; проверять не число
   открытых HTTP-соединений, а глубину очереди, age oldest job, throughput,
   успешность, ETA и стоимость.
